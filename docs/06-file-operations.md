# ファイル操作の実装要件

0.2.0で主要なキーボード操作を実装しました。更新はすべてOperationServiceと別プロセスのワーカーを経由します。ドラッグ転送、置換・フォルダ統合、再起動後のUndo復元は未実装です。

## 共通のジョブ状態

親ごとに1件を実行し、操作中は新しい更新要求を無効にします。起動前に要求をpendingとして記録し、結果に成功項目、失敗項目、中断の有無、変更の有無を分けて保持します。ワーカーが正常終了しない場合はuncertainとし、完了扱いや自動再実行をしません。「停止要求中」は中断完了ではありません。進捗は処理名と当該ファイルのコピー済みサイズで表示し、総量の分からない段階に100%表示をしません。

実行前に、選択元・宛先・権限・同名・同一実体・自分自身へのコピー・自分の子孫への移動を検査します。複数選択に親ディレクトリとその子が混在するときは二重処理を避けます。検査後の外部変更を想定し、書き込みの確定直前にも確認します。パスの文字列比較だけで同一ファイルと判断しません。

APIには文字列の配列やGFileを渡し、`sh -c`、`cp`、`mv`、`rm`のコマンド文字列を作りません。ファイル名に空白、先頭のハイフン、引用符、シェル記号があっても命令として解釈しません。

## 操作ごとの規則

| 操作 | 必須の挙動 |
|---|---|
| 新規フォルダ | 編集確定後に作成。同名があれば名前を再入力し、既存フォルダへ黙って統合しない |
| 名前変更 | `/`、NUL、`.`、`..`等を拒否。競合は上書きせず再入力。初版は単一項目のみ |
| コピー | 宛先の同一ファイルシステム内で一時名へ書き、成功した項目を確定。途中の内容を完成品の名前で見せない |
| 同一FS内の移動 | 可能な場合はrename系を使用し、競合条件を確認して確定 |
| 異なるFS間の移動 | コピーの確定と元の同一性確認ができた項目だけ元を削除。完了前に元を消さない |
| ごみ箱 | GIOのtrash機能を使用。利用不可・容量不足・権限不足なら説明して停止。完全削除へ自動変更しない |
| 完全削除 | 専用コマンドと確認ダイアログを通す。Undo対象外。ごみ箱失敗後の自動fallbackとして使わない |
| 開く | 通常の文書はOSの既定アプリへ渡す。実行可能ファイル・スクリプト・desktopファイルは自動実行せず、明示した実行操作を別扱いにする |

フォルダコピーは自前の再帰計画が必要です。GIOのcopyにフォルダを渡すだけで完了したことにしません。処理中はキャンセルを照会し、外部マウントが応答しない等のケースでは「停止要求中」を表示します。カーネルの中断不能I/Oに対して即時停止を保証しません。[GIO copy](https://docs.gtk.org/gio/method.File.copy.html)、[GIO trash](https://docs.gtk.org/gio/method.File.trash.html)

## 競合、途中失敗、メタデータ

貼り付け先の同名競合はスキップ／別名で両方保持／キャンセルを選びます。既定はスキップで、上書きとフォルダ統合は提供しません。方針は当該ジョブ内で適用します。同じフォルダへのコピーは別名、同じ場所への移動は変更なしになります。確定にはLinuxのrenameat2(RENAME_NOREPLACE)を使い、事前の空き確認後に同名が作られても上書きしません。

将来の置換・統合でも、種類の衝突を再帰削除で解決しません。変更前の復旧用コピーを保持できない条件ではUndo可能と表示しません。現在はdevice・inode・mode・size・mtime・ctimeとフォルダ内の一覧を照合します。外部プロセスが同時に変更するファイルについて、全ツリーの原子的な排他や整合性は保証しません。

キャンセルは未完了項目に適用し、すでに確定したコピーや移動を勝手に巻き戻しません。所有している一時ファイルだけを削除します。中断したジョブは記録しても、再起動後に自動再実行しません。

通常ファイルでは内容、更新時刻、利用者が設定可能な権限を保持します。setuid / setgidはコピー先へ付与しません。所有者を元に合わせる権限昇格を行いません。ACL・拡張属性・ハードリンク構造の完全保持は保証せず、結果のツールチップ・詳細へ記載します。コピーのデータバッファは64KiB、再帰確認は1項目あたり10万エントリ・相対パス128階層までです。上限を超える場合は説明して停止します。

## リンクと特殊ファイル

コピー・削除・再帰検索ではシンボリックリンク先をたどりません。リンク自体をコピー・移動・ごみ箱・削除します。フォルダへのリンクを利用者が開く操作と、再帰的な処理の追従は区別します。循環リンクでも無限再帰しません。

FIFO、ソケット、デバイスファイルは通常ファイルとして読み書きせず、初版のコピー・移動対象外として説明します。破損リンクはリンクとして表示し、リンク自体の操作を可能にします。生の名前をUTF-8へ可逆変換できない項目は、曖昧なパスによる更新を禁止します。

## クリップボードとドラッグ

`text/uri-list`、GNOMEの `x-special/gnome-copied-files`、KDEの `application/x-kde-cutselection` とアプリ独自の識別情報を扱います。URIはローカルファイルだけを受け付け、userinfo、HTTP、リモートホスト、query、fragmentを拒否します。形式変換の自動テストは実装済みですが、GNOME / KDEとの実機相互運用は後続の確認です。パス文字列だけの通常テキストから転送を推測しません。

Ctrl+Xは切り取りの予約だけで元を消しません。移動が成功した項目だけ予約から除き、失敗・中断項目は残します。処理中にクリップボードが変わった場合は変更しません。アプリ内のコピー／切り取りは選択時の同一性を記録し、貼り付け時に変わっていれば停止します。外部アプリからの転送は貼り付け時に記録します。

ドラッグ転送はまだ無効です。後続の実装では同一FSなら移動、異なるFSならコピーを既定とし、Ctrlでコピー、Shiftで移動を明示します。判断できないときはコピー／移動を選びます。リンク作成の修飾キー操作は初版対象外です。

## Undo / Redo

親ごとに直近20件、当該プロセス内の操作を管理します。取り消し可能性は結果と対象の現在の状態を確認して決めます。ジョブ記録はXDG_STATE_HOMEに置き、再起動後にUndoを自動復活させません。

逆操作は1項目2,048エントリ・JSON 512KiBまで記録し、結果メッセージ全体の上限を超える場合も取り消し対象外にします。複数項目の取り消しは実行前に全対象を照合し、確認後も各更新時に照合します。アプリ自身の名前変更ややり直しで識別情報が変わった場合は、ワーカーが照合できた変更だけを履歴へ反映します。外部編集を過去の操作の一部として信頼し直しません。

| 操作 | 初版のUndo |
|---|---|
| 新規フォルダ | 作成後も空で、同一実体である場合のみ削除 |
| 競合のない名前変更・同一FS移動 | 元の名前が空いていて、対象が同一実体なら戻す |
| コピー | このジョブが作成した未変更項目だけを取り除く。ユーザーが追記した内容を消さない |
| 異なるFS移動 | 初版は対象外。安全な逆方向ジョブの検証後に拡張 |
| ごみ箱 | 初版は対象外。OSのごみ箱から復元する案内を表示。正確なtrash IDによる復元は後続 |
| 置換・フォルダ統合・部分失敗・完全削除 | 初版は対象外。実行前後に対象外であることを示す |

初版で対象外の操作を実行したら、その親の既存Undo / Redo履歴をクリアして、次のCtrl+Zで過去の別操作を取り消す事故を防ぎます。Ctrl+Yは成功したUndoの再実行に限り、元の内容と競合条件を再確認します。入力欄では標準のテキストUndo / Redoを使います。

記録先は `$XDG_STATE_HOME/moooyooo-linux-explorer/jobs/<親ID>/<ジョブID>.json`。ディレクトリ0700・記録0600で、ファイル内容は保存しません。要求と結果には操作対象の実パスが含まれるため、共有・リポジトリ保存の対象にしません。同じ親の完了記録を直近20件に制限し、他の親や未完了・結果不明の記録は自動削除しません。
