# ファイル操作の実装要件

この文書は実装前の契約です。現在、実際のファイルを変更するアプリ機能はありません。

## 共通のジョブ状態

`queued → planning → running → waiting_for_choice → running → completed / partially_completed / cancelled / failed` を基本とします。cancel_requestedは中断完了ではありません。各結果に成功件数・失敗件数・中断件数を分けて持ちます。進捗の総量が未確定なら不定進捗を表示し、全件成功前に100%としません。

実行前に、選択元・宛先・権限・同名・同一実体・自分自身へのコピー・自分の子孫への移動を検査します。複数選択に親ディレクトリとその子が混在するときは二重処理を避けます。検査後の外部変更を想定し、書き込みの確定直前にも確認します。パスの文字列比較だけで同一ファイルと判断しません。

APIには文字列の配列やGFileを渡し、`sh -c`、`cp`、`mv`、`rm`のコマンド文字列を作りません。ファイル名に空白、先頭のハイフン、引用符、シェル記号があっても命令として解釈しません。

## 操作ごとの規則

| 操作 | 必須の挙動 |
|---|---|
| 新規フォルダ | 編集確定後に作成。同名があれば名前を再入力し、既存フォルダへ黙って統合しない |
| 名前変更 | `/`、NUL、`.`、`..`等を拒否。競合は上書きせず再入力。初版は単一項目のみ |
| コピー | 宛先の同一ファイルシステム内で一時名へ書き、成功した項目を確定。途中の内容を完成品の名前で見せない |
| 同一FS内の移動 | 可能な場合はrename系を使用し、競合条件を確認して確定 |
| 異なるFS間の移動 | コピーの確定と元の同一性確認ができた項目だけ元を削除。完了前に元を消さない |
| ごみ箱 | GIOのtrash機能を使用。利用不可・容量不足・権限不足なら説明して停止。完全削除へ自動変更しない |
| 完全削除 | 専用コマンドと確認ダイアログを通す。Undo対象外。ごみ箱失敗後の自動fallbackとして使わない |
| 開く | 通常の文書はOSの既定アプリへ渡す。実行可能ファイル・スクリプト・desktopファイルは自動実行せず、明示した実行操作を別扱いにする |

フォルダコピーは自前の再帰計画が必要です。GIOのcopyにフォルダを渡すだけで完了したことにしません。処理中はキャンセルを照会し、外部マウントが応答しない等のケースでは「停止要求中」を表示します。カーネルの中断不能I/Oに対して即時停止を保証しません。[GIO copy](https://docs.gtk.org/gio/method.File.copy.html)、[GIO trash](https://docs.gtk.org/gio/method.File.trash.html)

## 競合、途中失敗、メタデータ

競合時はスキップ／両方保持／ファイル置換／フォルダ統合／中止のうち、対象の種類に適した選択肢だけを出します。既定はスキップで、自動置換はしません。「以降も同じ」はジョブ内・同じ競合種別だけに有効です。両方保持の候補名はOSの排他的な作成で予約し、名前の空きを先に調べただけで上書きしません。

フォルダ統合でも同名の子を個別に扱います。ファイルとディレクトリの種類が衝突した場合にディレクトリを再帰削除して置き換えません。置換では宛先の内容が選択後に変わっていれば再確認し、古い内容の復旧用コピーを保持できない条件ではUndo可能と表示しません。外部プロセスが同時に書くファイルについて、アプリだけで整合性を保証しません。

キャンセルは未完了項目に適用し、すでに確定したコピーや移動を勝手に巻き戻しません。所有している一時ファイルだけを削除します。中断したジョブは記録しても、再起動後に自動再実行しません。

通常ファイルでは内容、更新時刻、利用者が設定可能な権限を保持します。setuid / setgidはコピー先へ付与しません。所有者を元に合わせる権限昇格を行いません。ACL・拡張属性・ハードリンク構造を保持できない場合はジョブ結果で明示し、バックアップ用途の完全複製と表示しません。大きなファイルを丸ごとメモリに載せず、バッファ上限を設けます。

## リンクと特殊ファイル

コピー・削除・再帰検索ではシンボリックリンク先をたどりません。リンク自体をコピー・移動・ごみ箱・削除します。フォルダへのリンクを利用者が開く操作と、再帰的な処理の追従は区別します。循環リンクでも無限再帰しません。

FIFO、ソケット、デバイスファイルは通常ファイルとして読み書きせず、初版のコピー・移動対象外として説明します。破損リンクはリンクとして表示し、リンク自体の操作を可能にします。生の名前をUTF-8へ可逆変換できない項目は、曖昧なパスによる更新を禁止します。

## クリップボードとドラッグ

`text/uri-list` とLinuxデスクトップで使われるコピー／切り取りの表現をadapterで扱います。URIはローカルファイルだけを受け付け、userinfo、HTTP、任意のネットワークURLを実行しません。外部アプリとの相互運用はGNOME / KDEの双方で確認し、認識できない形式はコピー／移動を推測して実行しません。

Ctrl+Xは切り取りの予約だけで、この段階では元を消しません。貼り付け成功した項目だけ予約を消し、失敗項目は結果に残します。同じ切り取り要求の多重貼り付けはジョブIDと元の存在を確認して防ぎます。

ドラッグは同一FSなら移動、異なるFSならコピーを既定とし、Ctrlでコピー、Shiftで移動を明示します。判断できないときはドロップ前にコピー／移動を選びます。ドラッグ中に操作種別をカーソルと宛先で示します。リンク作成の修飾キー操作は初版対象外です。

## Undo / Redo

親ごとに直近20件、当該プロセス内の操作を管理します。取り消し可能性は結果と対象の現在の状態を確認して決めます。ジョブ記録はXDG_STATE_HOMEに置き、再起動後にUndoを自動復活させません。

| 操作 | 初版のUndo |
|---|---|
| 新規フォルダ | 作成後も空で、同一実体である場合のみ削除 |
| 競合のない名前変更・同一FS移動 | 元の名前が空いていて、対象が同一実体なら戻す |
| コピー | このジョブが作成した未変更項目だけを取り除く。ユーザーが追記した内容を消さない |
| 異なるFS移動 | 初版は対象外。安全な逆方向ジョブの検証後に拡張 |
| ごみ箱 | 初版は対象外。OSのごみ箱から復元する案内を表示。正確なtrash IDによる復元は後続 |
| 置換・フォルダ統合・部分失敗・完全削除 | 初版は対象外。実行前後に対象外であることを示す |

初版で対象外の操作を実行したら、その親の既存Undo / Redo履歴をクリアして、次のCtrl+Zで過去の別操作を取り消す事故を防ぎます。Ctrl+Yは成功したUndoの再実行に限り、元の内容と競合条件を再確認します。入力欄では標準のテキストUndo / Redoを使います。
