# プロジェクトの保存形式

正本は [project.schema.json](../schemas/project.schema.json)。形式名は `moooyooo-linux-explorer-project`、schema_versionは1、拡張子は `.mlex-project.json` とします。[サンプル](../examples/sample-project.json)は架空の相対位置のみを含み、実際の業務情報はありません。

## 保存場所

| データ | 場所 |
|---|---|
| アプリ設定 | `$XDG_CONFIG_HOME/moooyooo-linux-explorer/settings.json` |
| 保存済みプロジェクトの既定位置 | `$XDG_DATA_HOME/moooyooo-linux-explorer/projects/<project-id>.mlex-project.json` |
| 最近使ったプロジェクト・復元記録・ジョブ記録 | `$XDG_STATE_HOME/moooyooo-linux-explorer/` |
| 再生成できるキャッシュ | `$XDG_CACHE_HOME/moooyooo-linux-explorer/` |
| プロセス間の一時情報 | `$XDG_RUNTIME_DIR/moooyooo-linux-explorer/` |

XDG変数が未設定の場合は仕様の既定値を使います。アプリ用ディレクトリは0700、プロジェクト・状態ファイルは0600を基本とします。任意の場所への「名前を付けて保存」もできますが、実際の業務プロジェクトを開発リポジトリへ保存しません。アプリから保存を選んだ場所が本開発リポジトリ内と分かる場合は拒否します。[XDG Base Directory Specification](https://specifications.freedesktop.org/basedir/latest/)

プロジェクトには個人のパスや業務名が入るため、公開資料ではありません。外部へ共有する操作はファイル保存だけに留め、自動同期・アップロードを行いません。

## フィールドと意味

| フィールド | 内容 |
|---|---|
| format / schema_version | 固定の形式識別子 / 整数の形式版 |
| project_id | UUID。名前を付けて保存で新しいプロジェクトを作る場合は新規発行 |
| revision | 保存成功ごとに増える整数。新規は1 |
| name | 1〜120文字の表示名。ファイルシステムの名前に直接利用しない |
| window | 親の論理ピクセルでの幅・高さ、最大化状態。画面の絶対位置は保存しない |
| layout | mdi / tabsと、free / tile_vertical / tile_horizontal / tile_grid |
| panes | 子の順序付き配列。0〜64件。同じ場所の子を複数保存できる |
| active_pane_id | アクティブな子のUUID。子が0件の場合のみnull |

子にはUUID、Location、表示モード、ソート、隠しファイル表示、列、ツリー幅、アイコンサイズ、通常時の矩形、通常／最小化／最大化状態を保存します。panesの配列順を子一覧とタブの順序とします。矩形はMDIの表示領域に対する0〜1の比率で保存し、再表示時に実際の領域と最小サイズへ補正します。スクリーン外の配置をそのまま再現しません。

列は名前・サイズ・種類・更新日時から重複なく選び、名前列は必須とします。列幅・スクロール・ツリーの展開済み全ノードはversion 1の保存対象外です。これらを追加する際は保存形式と互換性を更新します。

Locationのkindは `home_relative` または `absolute` です。home_relativeの空文字はホーム、それ以外はホーム基準の相対パスです。absoluteは `/` から始まるLinuxのローカルパスです。どちらもNUL、改行等の制御文字、`.` / `..` セグメントを許可しません。home_relativeは先頭 `/` を許可しません。パス区切りは `/`、シェル変数や `~` の展開はしません。別の利用者のホームを識別できる情報をhome_relativeへ付加しません。

戻る履歴、選択中ファイル名、検索文字列、クリップボード、ファイル内容、認証情報、実行コマンド、サムネイル、操作のUndo履歴はプロジェクトに含めません。JSONに未知のフィールドを勝手に付け足して有効化しません。

## 保存と競合

1. 保存対象ファイルは絶対位置を確定し、既存ファイルのシンボリックリンクを保存先として直接追従しない。リンクなら実体への保存または別名保存を利用者に選んでもらう。
2. 対象ごとのQLockFileを保持する。取得できない親ではプロジェクトの編集保存を無効にし、別名保存を可能にする。これは配置の保存に関する制御で、参照フォルダを読み取り専用にする意味ではない。
3. 読み込み時のrevisionと内容ハッシュを保存直前に再確認し、外部編集があれば上書きしない。再読込／別名保存／中止を提示する。
4. JSON全体を検証し、QSaveFileの一時ファイルとcommitを使う。直接書き込みへのfallbackは無効。書き込み・flush・確定に失敗したら未保存状態のまま、既存ファイルを残す。
5. 保存成功後にrevision、内容ハッシュ、未保存マークを更新する。

長時間開くプロジェクトのロックは経過時間だけで古いと判断して削除しません。プロセスが生存しているロックを強制解除しません。ロックが取得できないファイルシステムでは別名・ローカル保存へ誘導します。ネットワーク越しの完全な排他や電源断時の永続性をQSaveFileだけで保証しません。[QLockFile](https://doc.qt.io/qt-6.8/qlockfile.html)、[QSaveFile](https://doc.qt.io/qt-6.8/qsavefile.html)

## 未保存と異常終了

保存対象フィールドの変更だけをdirty判定に使います。選択・スクロール・一時検索・戻る履歴ではdirtyにしません。通常のフォルダ移動、子追加・削除、配置、表示設定の変更はdirtyになります。

復元記録は親インスタンスのUUIDごとにXDG_STATE_HOMEへ保存し、変更後2秒のまとめ書き、最長30秒間隔とします。元の保存済みプロジェクトを自動更新しません。未保存プロジェクトにも対応し、復元／破棄を利用者が選びます。正常終了後は対象の復元記録を消します。破損した復元記録を原本へ上書きしません。

## 読み込み

上限2MiB、UTF-8 JSON、重複キーなし、NaN等の非JSON数値なしを要求します。JSON Schemaと参照関係を検証してからウィンドウを作ります。UUIDの重複、active_pane_idの参照切れ、子0件で非null、矩形の範囲外、列の重複を拒否します。0件なら空のMDIを表示し、Ctrl+Nで追加できます。

未知の新しいschema_versionは説明して開かず、元ファイルを保持します。今後の旧形式変換は元のコピーを残し、変換後も検証してから保存します。現在はversion 1のみで、変換処理はありません。

構造が正しくてもフォルダが存在しない・読めない場合は、対応する子をエラー状態として残し、他の子の復元を続けます。自動作成や自動マウントは行いません。CLIとドラッグで受け取ったプロジェクトも同じ検証を通します。
