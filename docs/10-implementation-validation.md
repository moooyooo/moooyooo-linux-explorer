# 閲覧版の実装と検証

2026-10-09、バージョン0.1.0。設計のみの初回コミットに続き、C++20 / Qt Widgetsの実アプリを追加しました。

この文書は0.1.0時点の記録です。0.2.0の追加機能と現在の制限は[主要ファイル操作の検証記録](11-file-operation-validation.md)を参照してください。

## 実装した範囲

- 親1つにつき1プロセス。Ctrl+Alt+Nで親、Ctrl+N / Ctrl+Tで子を追加。最後の子を閉じても親を維持。
- 子ごとの場所、移動履歴、検索、選択、詳細／アイコン、隠しファイル、ツリー幅。共有の読み取り専用QFileSystemModelと子ごとのproxy。
- 自由配置、左右・上下・格子整列、タブ表示と並べ替え。通常時の位置を保持してMDIへ戻す。
- 入力欄の標準編集キーを優先し、IMEのpreedit中はコマンドを無効化。アドレス、検索、領域移動、プロパティ。
- JSON Schema v1の検証、重複キー・UTF-8・サイズ・深さ・UUID参照・場所・矩形の検査。
- QSaveFileによる保存、0600権限、継続ロック、外部編集・ファイル差し替えの検出、別名保存時の新しいID。
- XDG状態領域の復元記録。2秒debounce／30秒deadline、異常終了した記録の復元・破棄・保留。他プロセスの記録はロックで除外。
- ソースリポジトリへの実行時保存を拒否。リポジトリ内のサンプルを読むときはロックファイルも作らず、上書き不可にする。
- CLI、導入・診断・起動スクリプト、一時領域の架空デモ。

## 検証の再現

```sh
cmake --preset dev
cmake --build --preset dev --parallel 4
ctest --preset dev
python3 tools/check_spec.py
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
python3 tools/check_repository.py --worktree
```

CTestは保存形式と保存競合、offscreenでのキー・フォルダ表示・20子・MDI／タブ・復元、GUI不要のhelp／version、2つの独立GUIプロセスとCLIの異常終了コードを検査します。テスト用のパスは一時フォルダに生成し、実業務のフォルダを使いません。画像の生成は任意で、リポジトリ外に限定してください。

Pythonの既存15テストはスキーマ・秘密情報チェック・Git履歴の検査を検証します。公開前の検査は任意の個人情報が完全に存在しないことの証明ではなく、差分とメタデータの確認も合わせて実施します。

通常ビルドのCTestは5件すべて成功、仕様チェックとPythonの15テストも成功しました。ASan／UBSanビルドも同じ5件が成功しました。終了時の遅延通知による不正アクセスを検出・修正し、再検証しています。

この実行環境ではLeakSanitizerが終了時にptrace制限のエラーとなるため、リーク検査は未実施です。ASanのメモリアクセス検査とUBSanは有効のまま、次の条件で実行しました。通常の開発ホストではまず制限を付けずに実行してください。

```sh
cmake --preset asan
cmake --build --preset asan --parallel 4
ASAN_OPTIONS=detect_leaks=0 UBSAN_OPTIONS=halt_on_error=1 ctest --preset asan
```

## 実機確認と後続作業

エージェント環境からのWayland接続は `Operation not permitted`、X11接続も拒否されました。Qtのxcb依存にはリンク切れがありません。通常のターミナルで `python3 tools/demo.py` または `sh tools/run.sh` を実行して表示を確認します。デスクトップ実機のフォーカス・IME・既定アプリ連携はoffscreenだけでは確認済みとしません。

コピー・移動・削除・新規フォルダ・名前変更・クリップボード・Undo・プレビューは未実装です。実行ファイル、代表的なスクリプト拡張子、desktopファイルは閲覧版から起動しません。既定アプリ連携は利用者がファイルを開いたときだけです。

最近使ったプロジェクト一覧、プロジェクトのドラッグ受け入れ、列の表示選択UI、詳細な媒体切断／アクセスエラーの分類、配布用desktopエントリーは後続です。現在はCtrl+Oと保存ダイアログでプロジェクトを選びます。別名保存は既存ファイルの上書きを拒否し、新しい名前を要求します。

ネットワークファイルシステム、故障媒体、保存中の容量不足や電源断、10万件の列挙、メモリ・応答時間の予算、Qt 6.8でのビルド、GNOME／KDE／HiDPIは未評価です。同時保存は協調ロックと直前の同一性検査を使いますが、ロックを無視する外部プロセスとの厳密な原子的比較交換は保証しません。

GitHubへのremote登録・push・公開は行っていません。公開ライセンスと配布時の依存表示はM5で確定します。
