# 受け入れ条件と開発順序

## 実装の段階

| 段階 | 成果物 | 完了条件 |
|---|---|---|
| D0: 完了 | 開発環境の選定、仕様、JSON Schema、架空例、Git検査、初回コミット | 設計・サンプルの整合と公開前チェックが通る |
| M1: 閲覧できるMDI | CMake、親・子、ツリー・一覧、移動、キー、複数親 | 実ファイルを更新せず、20子と複数親を実機で操作できる |
| M2: 業務の切り替え | プロジェクト保存・復元、排他、復元記録 | 配置・場所を再現し、競合や破損で原本を壊さない |
| M3: ファイル整理 | 操作ワーカー、作成・変更・コピー・移動・ごみ箱・Undo | 架空ツリーで失敗とキャンセルを含む統合テストが通る |
| M4: 日常利用候補 | 限定プレビュー、性能改善、IME、HiDPI、OS連携 | Wayland / X11、GNOME / KDEで受け入れ条件を満たす |
| M5: 公開準備 | 配布物、ライセンス、依存一覧、利用案内、履歴検査 | 公開内容を確認し、利用者の公開指示に従ってGitHubへ反映 |

D0でGUIや実ファイル操作を完成扱いにしません。最初に見せる実アプリはM1の閲覧用プロトタイプとし、架空のフォルダツリーで確認します。

現在はM1〜M3の主要機能を実装し、保存・GUI・独立プロセス・ファイル操作を自動検証しています。実機GUI受け入れ、最近使ったプロジェクト一覧、異なるFSの移動・故障媒体などの検証は残っており、段階全体を完了とは扱いません。[閲覧版の記録](10-implementation-validation.md)と[操作版の記録](11-file-operation-validation.md)に範囲と残件を記載しています。

## 受け入れシナリオ

| ID | 検証内容 |
|---|---|
| A01 | 親Aに3子、親Bに2子を開く。Ctrl+Nは操作中の親だけに子を追加。親Aの終了後もBが使える |
| A02 | 両親を別プロジェクトで保存・終了・再表示し、場所・順序・表示・配置・アクティブな子が一致 |
| A03 | 同じフォルダを2子に開き、一方の表示・履歴・選択変更が他方に漏れない |
| A04 | MDI／タブ、整列、最大化／復元を繰り返しても配置と子の数を失わない |
| A05 | 同じプロジェクトを2親で開き、2つ目は原本を上書きできず別名保存できる |
| A06 | 外部編集、ロック保持、保存先の容量不足、書込失敗、途中終了で元のJSONが破損しない |
| A07 | 破損、重複キー、未知の版、上限超過、参照切れ、危険なLocationを拒否。無いフォルダは子だけエラー |
| A08 | 入力欄のDelete・Backspace・Ctrl+Z等でファイルを変更しない。IME変換中も同様 |
| A09 | Ctrl+Shift+Nでフォルダ作成、Ctrl+Nで子追加、Ctrl+Alt+Nで親追加。Ctrl+Wで最後の子だけを閉じる |
| A10 | 外部変更・並べ替え・再読み込み後の選択とコマンド対象が食い違わない |
| A11 | 日本語、空白、引用符、先頭ハイフン、シェル記号を含む名前を正しく扱う |
| A12 | コピー競合・容量不足・権限不足・途中キャンセルで元データを失わず、部分成功を正しく表示 |
| A13 | 異なるFS移動、同一実体、子孫への移動、競合発生中の外部編集を扱う |
| A14 | ごみ箱失敗が完全削除へ変わらない。完全削除の確認をキャンセルすると変更しない |
| A15 | シンボリックリンク、循環、FIFO等、非UTF-8名で誤った対象を変更しない |
| A16 | Undo時に対象が更新・削除・再作成されていたら停止し、他の内容を消さない |
| A17 | 外部ファイラ・子間・親間のコピー／移動、修飾キー、Waylandのクリップボードを確認 |
| A18 | 保存済みの画面より狭い画面・倍率変更で子を画面内に戻し、日本語・フォーカス表示が読める |
| A19 | プレビューの上限・不正画像・ワーカー異常終了がGUIやファイル操作に波及しない |
| A20 | 本番パス・トークンがログやクラッシュ資料に自動収録されず、設定と履歴がリポジトリ外に置かれる |

テスト用のファイルツリーはQTemporaryDir等でリポジトリ外に生成します。実業務のフォルダ、本人のホームの一覧、実際のごみ箱をテストに使いません。ごみ箱の自動テストはHOMEとXDG_DATA_HOMEを一時領域へ隔離し、ワーカーを別プロセスで実行します。デスクトップ統合は使い捨てのテストユーザー／VMで確認します。

## 性能の受け入れ目標

以下は未測定の初期予算です。リリースビルド、4コア以上・メモリ8GiB以上・ローカルSSD、プレビューOFFで測定し、機種・OS・Qt版・初回／キャッシュ済みを記録します。

| 測定 | 目標 |
|---|---|
| ローカルの子1つで起動し操作可能 | 2秒以内 |
| 健全なローカルフォルダ・1万件の列挙から一覧安定まで | 2秒以内 |
| 既存一覧の選択・フォーカス移動 | 95パーセンタイル100ms以内 |
| 20子復元のシェル表示・入力可能 | 2秒以内。フォルダ読み込みは順次 |
| GUIメモリ | 1子でRSS 120MiB以下、20子・合計10万件でRSS 300MiB以下を初期目標 |
| ファイルコピー中のGUI応答 | ローカル試験で200ms超の入力停止を生まない |
| コピーのアプリ用バッファ | ワーカー1つにつき16MiB以内 |
| 起動直後の待機 | コピー／プレビュー用プロセスの常駐なし |

10万件の単一フォルダ、20子、複数親、低速マウント、取り外し、監視上限到達をストレス試験に含めます。ネットワーク／故障媒体の完了時間や中断不能I/Oの終了時間は固定値を保証しません。性能を満たすためにファイル操作の確認や整合性を省略しません。

## 自動検証の実装方針

Qt Testで状態・モデル・コマンドとGUI操作を検証し、CTestで統合します。純粋なモデルと保存の検証はGUIなしで実行します。offscreenはGUIスモークに使い、Wayland / X11、IME、外部クリップボード、既定アプリ、ごみ箱をoffscreenだけで確認済みとしません。

UI実装後にLinux CIを追加し、依存・Qtの実バージョンを固定したビルド記録を残します。導入前のCIを成功したように見せるための空ジョブは作りません。公開前チェックをCIにも追加しますが、ローカルフックの検査も継続します。
